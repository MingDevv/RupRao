[บทที่ 1] โปรเจกต์นี้คืออะไร อยู่ที่ไหน
- สร้างเว็บ "RupRao": อัปโหลดเซลฟี่ 1 รูป ให้ AI หาหน้าตัวเองจากรูปงานโรงเรียนทั้งหมด
- โฟลเดอร์โปรเจกต์: .../workspace/RupRao (เคยชื่อ photo-finder ก่อนเปลี่ยนชื่อเองเมื่อ 3 พ.ย.)
- ไฟล์สำคัญ: step1_detect_faces.py (สคริปต์แรก), data/input/ (รูปใส่ตรงนี้), data/output/ (ผลลัพธ์)
- แผนทั้งหมดอยู่ที่ไฟล์ แผนทั้งหมด.md อ่านก่อนลงมือทุกครั้ง

[บทที่ 2] venv คืออะไร (สร้างครั้งแรก 3 พ.ย.)
- venv = "ห้องแยกไลบรารีของแต่ละโปรเจกต์" กันโปรเจกต์อื่นชนกันเวอร์ชันไม่ตรง
- สร้าง: python3 -m venv venv  |  ใช้ของในนั้น: venv/bin/python หรือ venv/bin/pip
- โปรแกรมเมอร์จริงทำแบบนี้ทุกโปรเจกต์ ถือเป็นมารยาทพื้นฐาน

[บทที่ 3] ไลบรารี (pip)
- ไลบรารี = ชุดเครื่องมือที่คนอื่นเขียนไว้ให้ใช้ฟรี ไม่ต้องเขียนเองทุกอย่าง
- ติดตั้ง: venv/bin/pip install ชื่อไลบรารี
- ของที่โปรเจกต์นี้ใช้: opencv (จัดการรูป), numpy (คำนวณตัวเลข), onnxruntime (รันโมเดล AI),
  insightface (จับหน้า + ลายเซ็นหน้า), pillow (ย่อ/ต่อรูป)
- ทริค: บางทีต้องเลือกเวอร์ชัน เช่น "numpy<2" กันชนกับ insightface

[บทที่ 4] รูปภาพในสายตาคอมพิวเตอร์
- รูป = ตารางตัวเลขมหึมา (แต่ละพิกเซล = เลข 0-255 สามชุด: แดง เขียว น้ำเงิน)
- รูปทดสอบเรา 1300x420 = 546,000 ช่อง — AI ไม่มีตา อ่านตัวเลขล้วนๆ แล้วเดาว่ากลุ่มไหนคือ "หน้า"

[บทที่ 5] AI จับหน้า (Face Detection) ทำงานยังไง ⭐ หัวใจวันแรก
1) โมเดล SCRFD เคยดูหน้าคนนับล้านใบพร้อมคำตอบว่าหน้าอยู่ตรงไหน (supervised learning)
   มันไม่ได้รับกฎว่า "หน้า = ตา 2 จมูก 1" แต่เขียนกฎเองจากตัวอย่าง — นี่คือ Machine Learning
2) มองแบบมี "ชั้น" จากง่ายไปยาก: ขอบ/เส้น/เงา -> วงตา/จมูก/ปาก -> "โครงหน้ามนุษย์!"
3) ไล่สแกนทุกบริเวณของรูปย่อ 640px (ตัวแปร det_size) หลายสเกล ถามซ้ำ "ตรงนี้มีหน้ามั้ย?"
4) คำตอบไม่ใช่ ใช่/ไม่ใช่ แต่เป็น "คะแนนความมั่นใจ" 0.0-1.0 (เราได้ 0.81-0.88 มาแล้ว)
5) คนเป็นคนตั้งกติกาว่าตัดกันที่เท่าไหร่ (threshold ~0.5):
   ลดลง = เจอเยอะแต่หลอกเยอะ / เพิ่มขึ้น = เน้นชัวร์แต่พลาดหน้าเล็ก
   การจูนเลขนี้คือสกิลจริงของคนทำ ML — ตอนทำ RupRao จริงต้องจูนด้วยมือ
6) โมเดลยังหา "จุด landmark" ได้ (ตา คิ้ว จมูก ปาก รวม 106 จุด) ใช้จัดหน้าให้ตรง
   ก่อนขั้นต่อไป (ไฟล์ 2d106det.onnx ใน log ก็คือตัวนี้)
7) กรอบที่ซ้ำทับกัน ตัดให้เหลืออันที่มั่นใจสุด (เทคนิคชื่อ NMS)

[บทที่ 6] โมเดล AI เป็นแค่ "ไฟล์"
- โมเดล = ไฟล์ .onnx (ของเราโหลด 330MB เก็บที่ ~/.insightface/models/buffalo_l/)
- โหลดครั้งเดียวใช้ซ้ำได้ตลอด รอบหลังเร็วขึ้นมาก ไม่ต้องโหลดใหม่

[บทที่ 7] git พื้นฐาน ⭐ ใช้ตลอดชีวิตโปรแกรมเมอร์
- git = ไทม์แมชชีนของโค้ด จุด save แต่ละจุดเรียก "commit"
- คำสั่งหลัก: git add -A -> git commit -m "คำอธิบายสั้นๆ" -> git push (ส่งขึ้น GitHub)
- .gitignore = รายชื่อไฟล์ที่ "ห้าม" ขึ้น GitHub (ของเรา: venv/, รูปทุกไฟล์, ขยะระบบ)
- เหตุผลสำคัญ: รูปหน้าคน = ข้อมูลส่วนบุคคล (PDPA) ห้ามขึ้นเน็ตแม้ repo จะ private
- commit แรกของเรา: 8a2d61c "step1: สคริปต์จับหน้า + โครงโปรเจกต์ photo-finder 🚀"
- ข้อสังเกตจากของจริง: เปลี่ยนชื่อโฟลเดอร์โปรเจกต์ได้เรื่อยๆ git ไม่หาย เพราะ
  มันตามไฟล์ ไม่ได้ผูกกับที่อยู่โฟลเดอร์

[บทที่ 8] เมื่อเน็ตบล็อก: SSH กับ HTTPS
- ส่งโค้ดขึ้น GitHub ได้ 2 ทาง: SSH (พอร์ต 22) กับ HTTPS (พอร์ต 443)
- เน็ตเราบล็อก SSH (ลอง 22 แล้ว timeout, ลองทาง ssh.github.com:443 ก็ timeout)
- ทางแก้: ใช้ HTTPS ล้วน + ล็อกอินผ่าน gh (รับโค้ด 6 หลัก -> เปิด github.com/login/device
  -> วางโค้ด -> Authorize) — พิสูจน์แล้วว่า HTTPS ผ่านชัวร์ (โมเดล 330MB ก็โหลดผ่าน 443 มาแล้ว)

[บทที่ 9] อ่าน log ให้เป็น
- ข้อความ "Warning" ส่วนใหญ่ไม่ใช่ปัญหา (เช่น NotOpenSSLWarning ของ macOS ให้ข้ามได้)
- สิ่งที่ต้องดูคือ: ตัวเลขผลลัพธ์ / Error ตอนท้าย / ไฟล์ที่ถูกสร้าง
- งานที่ใช้เวลานาน (โหลดโมเดล, สแกนรูปเยอะ) ให้รันเป็น background แล้วไปทำอย่างอื่นต่อได้
- โหลดของใหญ่ทีละครั้งพังได้ อย่าเพิ่งตกใจ รันซ้ำหลายทีจนได้ (โมเดลเราโหลด 2 รอบถึงครบ)

[กำลังจะเรียนในคาบหน้า]
- Embedding: เปลี่ยนหน้าคนเป็น "ลายเซ็น" 512 ตัวเลข — รูปลับว่า AI แยกคนได้ยังไง
- Cosine similarity: เลขเดียวบอกว่าหน้าสองหน้าเหมือนกันแค่ไหน (1 = คนเดียวกัน, 0 = ไม่เกี่ยว)
- FAISS: ค้นลายเซ็นนับล้านรายการจบในไม่กี่มิลลิวินาที (เทคนิคเดียวกับ ChatGPT หาข้อมูล)
